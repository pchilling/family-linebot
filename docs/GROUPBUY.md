# 團購(Phase 35)— 規格

2026-11-07 Peter 定案。對客人的用詞:「攤位」「團購」「追蹤這家店」。不叫會員(避免跟多特瑞的會員混淆)。

## 一、為什麼要做

個人賣家常見的賣法是「先收單、截止後統一向供應商訂貨、到貨再分送」,也就是團購 / 代購。
現在平台只有「現貨直接出」一條路。團購要有自己的商品列表、自己的開團節奏,而且攤主要能把它鎖給追蹤者看。

## 二、入口與名稱

- 手機(公開網頁、LINE 商店):店名下方兩個分頁「攤位」「團購」,「團購」旁一個綠點。
  **2026-11-08 Peter 改:只有「有收單中的團」時才出現分頁列;沒開團就只有攤位,看不到團購。** 不另做開關,開團就出現、結束就消失。
- 電腦版公開頁:頁首選單「攤位 · 團購 · 查訂單」,不做分頁;同樣只有收單中才有「團購」這一項。
- 網址 `/{slug}/groupbuy`,同時是攤主的邀請連結。
- 其他對客人講的「商店」維持不動,只有這兩個分頁叫「攤位」「團購」。

## 三、商品

- `products.channel`:`'stall'`(攤位,預設)或 `'groupbuy'`(團購),二選一。團購商品只出現在團購分頁、只在開團期間能買。
- `products.track_stock`:管理庫存開關,預設 `true`。切成團購時後台自動改成 `false`,攤主可再打開。
  `false` 的商品:結帳不檢查庫存、下單不扣庫存(trigger 跳過),後台庫存頁顯示「不管理」。
- 同一樣東西想兩邊賣就複製商品,不做「兩邊都賣」。

## 四、團(開團到結團)

- 表 `group_buys`:tenant_id、name、description、ends_at(可空 = 手動截止)、expected_arrival_on(可空)、status、notify_on_open、created_at、closed_at、ordered_at、arrived_at、done_at。
- 同一攤位同時只能有一團 `open`。
- 狀態:`draft` → `open`(收單中)→ `closed`(已截止)→ `ordered`(已訂貨)→ `arrived`(已到貨)→ `done`(結團)。
  `open` 且 `ends_at < now()` 一律視為 `closed`(讀取時算,不靠排程);攤主也能提前截止。
  `closed` 且還沒 `ordered` 可以「重新開放」回 `open`。
- 開團時可勾「推 LINE 通知給全部好友」:送出前顯示會推給幾人,並提醒推播額度。
- 沒開團:客人看不到團購分頁(2026-11-08 改);直接打 `/{slug}/groupbuy` 網址(例如舊的邀請連結)還是開得到,
  上面一張灰卡「目前沒開團」+ 上一團的狀態;商品灰掉、不能加入。
  **「開團通知我」(Phase 37,2026-11-08 已做)**:灰卡上一顆按鈕,登記在 `group_buy_notify_requests`;沒登入先登入(帶 notify=1 回來自動登記)。
  只能推 LINE:有 LINE 且是這個攤位好友的人,開團時推開團卡(攤主有勾「推全部好友」時他們已經收到,只標記);沒 LINE 的會員看到的是說明不是按鈕。
  推過寫 notified_at,下一團要再按一次。

## 五、購物車與結帳

- 一個購物車,不分兩車。
- 結帳明細分兩組:「攤位 · 下單後 1–3 個工作天出貨」「團購 · 團名 · 預計 MM/DD 到貨」;團購組下方提醒「整張單會等到貨後一起出,想先拿現貨請分開下單」。
- `orders.group_buy_id`:訂單裡有團購商品就記當時 `open` 的團。
- 送單時 server 再驗一次:團購商品所屬的團必須還是 `open`,否則整張擋下:「本團已截止,請移除團購商品再送出」。
- 折扣碼、滿額贈、免運門檻照現有規則算整張單,不分組。
- 客人訂單頁時間軸(Phase 30 直式)多一步「等待團購到貨」,顯示預計到貨日;團 `arrived` 後打勾。
- 出貨單(app/print)上的團購品標「團購」。

## 六、攤主後台

- 左側選單多「團購」:
  - 列表:團名、狀態、截止、幾筆幾人、金額;依狀態給「看詳情 / 提前截止 / 重新開放 / 標已訂貨 / 標到貨 / 結團」。
  - 開團表單:團名、說明、截止時間、預計到貨日、推播勾選。「這團賣什麼」= 所有 channel = groupbuy 的商品,顯示件數並連到商品頁。
  - 團詳情:四格(訂單數 / 人數、已付款、金額、件數)、五步流程、彙總單、本團訂單。
  - 彙總單按「商品 × 規格」列件數與金額,同時顯示「已付款」「全部(含待核帳)」兩個數字;可匯出 CSV。
  - 按「標到貨」→ 推 LINE 通知給本團每張單的 LINE 客人(有 line_user_id 才推),文案帶訂單連結。
- 商品編輯頁多「賣在哪裡」(攤位 / 團購)與「管理庫存」。
- 設定 → 行銷多「團購」區:「團購只給追蹤者看」開關、邀請連結(複製)。「追蹤要核准」先不做,畫面標之後提供。
- 客戶頁多一欄「追蹤」:追蹤中 / LINE 好友 / 訪客,可篩。

## 七、追蹤這家店

- 表 `tenant_followers`:tenant_id、platform_user_id、created_at,unique(tenant_id, platform_user_id)。
- `tenants.groupbuy_followers_only boolean default false`。
- **追蹤要經攤主同意(Phase 37,2026-11-08 已做)**:`tenants.groupbuy_follow_approval`,預設關。開著時按「追蹤這家店」先是申請
  (`tenant_followers.status = 'pending'`),攤主在後台「團購」頁的「等你核准的追蹤申請」核准 / 拒絕;只認 approved 為追蹤。
  LINE 好友不用核准(本來就在 LINE 裡)。客人在門上與我的訂單頁看到「申請中」,可以取消申請。
- 關著:團購分頁誰都看得到。
- 開著:
  - 沒登入或沒追蹤的人,團購分頁只看到一扇門:「團購只開放給追蹤這家店的人」+「登入並追蹤這家店」。商品、價格、團名都不送到前端(server 端擋,不是畫面藏)。
  - 按下去走現有登入視窗,多一句「登入後會自動追蹤這家店」;登入回來自動寫入 tenant_followers,回到團購分頁顯示內容,toast「已追蹤 ○○」。
  - LINE 商店:加了官方帳號(users 表有紀錄)自動算追蹤,看不到門。
  - 團購頁 `robots: noindex`。
- 「我的訂單」頁一張追蹤卡:追蹤中 · 起始日 · 「取消追蹤」;沒追蹤的人是一顆「追蹤這家店」。

## 八、通知

- 開團(可選):推給攤位全部 LINE 好友。
- 到貨:推給本團每張單的 LINE 客人。
- 網頁版、非 LINE 的客人沒有通知管道,只能看訂單頁;信箱通知等 Resend 設好再補。

## 九、不做(這一版)

- 團購專屬價格(用商品現價,含特價與量購價)。
- 「開團時通知我」名單。
- 追蹤要核准。
- 同時多團。
- 到貨後再付款。
