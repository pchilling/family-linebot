# 超商取貨第二階段(Phase 36)— 規格

2026-11-08 Peter 定案。方向:**平台不接任何物流 API**,攤主用自己的 7-ELEVEN 賣貨便 / 全家好賣+ 寄件,
取貨付款的錢由超商直接撥給攤主,平台完全不經手。平台做的是把這條手動流程做順。

## 一、為什麼這樣做

- 之後的攤主大多是沒有公司的個人,不會去辦綠界或其他物流商;要他們申請物流、綁帳號、看撥款,門檻太高。
- 賣貨便 / 好賣+ 本來就是給個人用的,手機號碼就能開,取貨付款也支援,錢直接撥給攤主。
- 如果平台統一申請一個物流帳號幫大家寄,取貨付款的錢會先進 NEOP 再撥出去,變成代收代付,跟「平台不接金流」相反,運費也得跟每個攤主月結。
- 第一階段(Phase 29,2026-11-01)已經有:網站結帳選 7-ELEVEN / 全家店到店、客人填門市店名 + 店號、訂單存 cvs 欄位、後台按已寄出時必填寄件單號。
  LINE 商店還不支援店到店,取貨付款也沒有。這一階段補這兩塊,再把後台寄件做順。

## 二、原則

1. 攤主不用申請任何東西、不用填任何金鑰。
2. 收款方式有在「設定 → 收款」打勾的才會出現在結帳(全站既有規則),取貨付款也一樣,預設關。
3. 取貨付款的錢不經平台;後台的「已收款」只是攤主自己記帳。
4. 7-ELEVEN、全家各自「同一家寄、同一家取」,維持第一階段的兩個配送方式(key `cvs_711` / `cvs_family`)。

## 三、收款方式「超商取貨付款」卡

- 「設定 → 收款」第五張卡,跟匯款 / 掃碼 / LINE Pay / 綠界並列,預設關。
- 欄位:
  - 開關 `enabled`。
  - 給客人的說明 `note`(選填),顯示在結帳選項下方與訂單頁。例:「到店取貨時付現給店員,包裹到店後 7 天內要取」。
  - 單筆上限 `max_twd`(選填,空 = 不限)。超過上限的單結帳不顯示這個選項。
    上限依攤主用的超商規定自己填,卡上提示「例:全家好賣+ 10,000」;平台不寫死數字(11/8 查不到 7-ELEVEN 官方上限,只有理賠上限 20,000)。
- 存 `tenants.cod_payment jsonb`:`{ enabled, note, max_twd }`。寫法比照 Phase 27 的 `qr_payment`、Phase 28 的 `bank_transfer`。
- 這張卡只有在攤位至少有一個超商店到店配送方式時才有意義;沒有的話卡上提示「先到配送分頁加超商店到店」,開關仍可開。

## 四、結帳(網站 + LINE 商店一起)

- **LINE 商店補上店到店**:配送方式列出 7-ELEVEN / 全家店到店(現在 LIFF 載入時濾掉、送單時擋住,兩處都放開)。
  選了之後出現:取件人真名、手機(超商規定,沿用網站文案)、門市名稱、門市店號,附官方門市查詢連結(`lib/cvs.ts` 的 `mapUrl`)。
  欄位、驗證、錯誤訊息跟網站一致,送單走同一支驗證。
- **付款方式多「超商取貨付款」**(網站 + LIFF):
  - 只在「配送選了超商店到店」且「攤主有開 `cod_payment.enabled`」且「應付 ≤ `max_twd`(有設的話)」時出現;選宅配、門市自取看不到。
  - 配送切回宅配 / 自取時,若付款方式停在取貨付款,自動清掉並要客人重選。
  - 選項文案:「超商取貨付款」+ 一行「到店取貨時付款 NT$ X(含運費)」+ 攤主的 `note`。
  - 應付 = 商品小計 − 折扣碼 + 運費,全額到店付;折扣碼、滿額贈照常適用。
- 送單時 server 再驗一次:配送是 cvs、`cod_payment.enabled`、金額沒超上限,不符就整張擋下並說明。
- 這種單寫入:`payment_method = 'cod'`、`payment_status = 'pending'`、`status = 'open'`。
  不產生任何金流請求,下單完成直接進訂單頁。

## 五、客人的訂單頁與狀態

- 取貨付款的單**不顯示匯款資訊、不顯示回報後五碼**,改顯示一張「到店付款」卡:
  「到店取貨時付款 NT$ X · 門市:7-ELEVEN 大安門市(店號 123456)· 包裹到店後請在 7 天內領取」+ 攤主的 `note`。
- 時間軸(沿用 Phase 30 直式時間軸,步驟換成):
  1. 下單完成
  2. 賣家寄出 — 顯示寄件單號 + 官方查件連結(`trackUrl`);還沒寄顯示「賣家備貨中,1–3 個工作天寄出」
  3. 到店取貨付款 — 到店後付 NT$ X
  4. 完成
- 「3 天內未付款訂單會自動取消」這句不出現在取貨付款的單。
- **排程 `app/api/cron/expire-orders` 的逾期未付自動取消一律跳過 `payment_method = 'cod'`**,不然會把等出貨的單砍掉。
- 狀態對照(訂單頁與後台選單文案):`open` 待出貨 / `shipped` 已寄出 / `delivered` 已取貨 / `cancelled` 已取消。

## 六、後台

- **訂單詳情**(店到店的單,不限取貨付款):多一顆「複製寄件資料」,一段純文字,貼進賣貨便 / 好賣+ 就好:
  ```
  收件人:王小明
  手機:0912345678
  門市:7-ELEVEN 大安門市(店號 123456)
  取貨付款:NT$ 396(含運)   ← 不是取貨付款的單寫「已付款,取貨不付款」
  訂單:OW-202611-0010
  ```
- 已寄出照舊必填寄件單號(Phase 29)。
- **收款確認**:客人取貨、超商撥款後,攤主在訂單按「已收款」→ `status = 'delivered'`、`payment_status = 'paid'`、`paid_at = now()`。
  沿用匯款的收款確認按鈕,取貨付款的單上文案改「超商已撥款,確認收款」。
- **對帳頁**多一區「到店付款待確認」:`payment_method = 'cod'` 且 `status = 'shipped'` 且 `payment_status = 'pending'` 的單,
  顯示單號、金額、寄出幾天;超過 14 天標黃提醒攤主去查有沒有被退回。
- **逾期未取被退回**:攤主把訂單改「已取消」(庫存由現有 trigger 自動退),備註寫「逾期未取」。這版不另開狀態。
- **出貨單**(`app/print/[tenant]/order/[id]`):店到店的單印門市與店號;取貨付款的單印「取貨付款 NT$ X」。
- 訂單列表的付款欄顯示「取貨付款」。

## 七、LINE 通知

- 下單完成:取貨付款的單文案改成「到店取貨時付款 NT$ X」,不附匯款資訊。
- 已寄出:**實作時發現後台按「已寄出」原本不會推任何 LINE 通知**,這版補上(所有有綁 LINE 好友的單都推,不限取貨付款):
  一則文字,帶門市、寄件單號,取貨付款的單多一行「到店取貨時付款 NT$ X」,最後附訂單連結。
- 到店提醒不做,超商自己會發簡訊。
- 收款確認後不另推通知(客人已經拿到貨了)。

## 八、不做

- 不接綠界、速買配或任何物流 API;不做電子地圖;不做寄件單自動建立、物流狀態自動回寫。
- 萊爾富、OK 這版不加。
- 平台不代收任何款項。
- 不做「逾期未取」獨立狀態。

- 沒有新表。SQL 照慣例記進 `db/schema.sql` 與 `docs/progress.md`。
